# Upgrading

**Read this before upgrading a deployment.** One section per released version, newest first. A
version with no operator-visible change says so explicitly rather than being absent — an absent
section is indistinguishable from one nobody wrote.

## Why this file exists, and what it is not

Release notes for this workspace are per-crate and generated by `release-plz` from **commit
subjects** (see [`CHANGELOG.md`](../CHANGELOG.md)). A subject is one line. It cannot carry "upgrade
these two things together or the stack will not boot", so a hazard recorded only in a commit body,
`ASSUMPTIONS.md` or an issue reaches nobody performing an upgrade.

That gap was accepted deliberately rather than left implicit — see `DECISIONS.md`, U-514. This file
is the named place operator-visible changes go, and `docker/assert-upgrade-notes.sh` fails the build
if the current workspace version has no section here.

This is **not** a changelog. It carries only what changes an operator's actions: configuration whose
meaning changed, an upgrade that must be ordered, a default that moved, a removal. Everything else
belongs in the per-crate changelogs.

## 0.1.4

**Upgrade the image and `docker/docker-compose.yml` together.** If you deploy the compose recipe,
pulling one without the other does not boot.

`docker-compose.yml` now passes `ACDP_REGISTRY_AUTH__ENABLED` through as an **empty** value when you
have not set `ACDP_REGISTRY_AUTH_ENABLED` (this is the `${VAR:-}` form, and it is deliberate — see
below). A registry binary from **before** 0.1.4 rejects an empty boolean outright with
`invalid type: string ""`, so:

| you pull | result |
|---|---|
| new compose file + new image | boots |
| new compose file + **old** image | **fails at startup**, before serving a request |
| old compose file + new image | boots |

**What changed underneath.** An empty `ACDP_REGISTRY_*` environment variable is now treated as
**absent** rather than as an override of the config file. Previously an empty value either replaced
your TOML value with `""` (string fields) or failed the config load outright (numbers, booleans, and
list fields). This exists because `docker compose` renders an *unset* variable as *set-to-empty*
rather than absent, so every `${VAR:-}` passthrough silently overwrote the config file.

**If you relied on an empty variable to clear a config-file value**, that no longer works — set the
variable to the value you want, or remove it from the config file. Any empty variable that was
ignored is named in a startup `warn!`, so a log line tells you which.

**New capability:** you can now enable auth from the environment —
`ACDP_REGISTRY_AUTH_ENABLED=true` — where previously the compose recipe offered no env path and you
had to edit `config.docker.toml`. Note that only the `${VAR:-}` form is safe to add as a
passthrough: `${VAR:-false}` renders the literal string `"false"`, which is a real value and would
override a `true` you set in your config file.

## 0.1.3 and earlier

No operator-visible upgrade steps recorded. These versions predate this file; their changes are in
the per-crate changelogs and were not reviewed against this file's criteria retroactively. Absence
here is not a statement that none existed.
