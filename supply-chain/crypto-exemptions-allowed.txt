# Crypto-critical (crate, version) pairs that MAY stay exempted in
# supply-chain/config.toml rather than audited (#405). Read by
# .github/scripts/check_crypto_exemptions.py.
#
# Format, one entry per line:
#   <crate> <version> <tracking> <reason...>
#   <crate>     a name from supply-chain/crypto-critical.txt
#   <version>   the exact exempted version (no ranges, no wildcards)
#   <tracking>  the issue that ends the exemption, `<repo>#<n>` or `#<n>`
#   <reason>    free text, required: why this version is exempted today
# A line whose first non-blank character is `#` is a comment.
#
# This list may only SHRINK as audits land. The guard fails both ways:
#   - a crypto-critical crate exempted at a version not listed here
#     (a bump must be audited, not re-exempted, or added here in review);
#   - a listed pair that config.toml no longer exempts (stale: delete the
#     line in the same PR that removes the exemption).
#
# Two kinds of entry today:
#   older-line   a version acdp-rs does not lock, so its audits will never
#                cover it. Mostly the RustCrypto 0.10/0.13 line pulled in by
#                jsonwebtoken, ed25519-dalek 2.x and sqlx. Ends with an audit
#                here, or when that dependency moves to the current line.
#   import-lag   acdp-rs's audits.toml on main already certifies this (or a
#                neighbouring) version, but supply-chain/imports.lock predates
#                it. Ends with `cargo vet regenerate imports` +
#                `cargo vet regenerate exemptions` (review the imports diff),
#                tracked in #410.
